Refactor Action List and General Rules for Parser::HPC

File target
- lib/Parser/HPC.pm

General rules (design contract)
1) Every directive must be defined by three attributes:
   - Scope: where it is legal (global, data, code, stack)
   - Cardinality: 0..1, 1, or 0..n
   - Effect: persistent parser state vs side effect only

2) Keep parser state in object fields.
   - Use simple fields with undef/non-undef semantics where possible.
   - Suggested fields: _title, _radix, _locals, _scope, _local_scope, _symbols.

3) Separate structural grammar from scope-local statements.
   - parse() handles top-level structure/order.
   - block/section parsers handle scope-local alternatives.

4) Scope legality should be explicit, not implicit by call path.
   - Track current scope in _scope.
   - Enter segment scope explicitly and restore automatically.

5) Error strategy must be consistent.
   - Optional parse paths: return no-match cleanly.
   - Required grammar parts: fail with domain-specific message.
   - Avoid ad-hoc eval for control flow where a direct parse/fail pattern is available.

6) Duplicate-once directives should fail hard.
   - For 0..1 directives (e.g., TITLE), second occurrence is a syntax error.

7) Document internal fields and directive policy in POD.
   - Internal state: name, type, initial value, semantics, mutability.
   - Directive policy: scope + cardinality + effect.

Suggested directive policy (current discussion)
- %TITLE:
  - Scope: global
  - Cardinality: 0..1
  - Effect: persistent (_title)
  - Duplicate: fail
- DISPLAY:
  - Scope: configurable (currently broad)
  - Cardinality: 0..n
  - Effect: side effect only (warn)
- RADIX:
  - Scope: configurable (currently broad)
  - Cardinality: 0..n
  - Effect: persistent (_radix)
- LOCALS/NOLOCALS:
  - Scope: code only (if that is the adopted policy)
  - Cardinality: 0..n
  - Effect: persistent (_locals)
- IDEAL / LANGUAGE / MODEL:
  - Structural required grammar in fixed parse order

Concrete refactor actions (ordered)
1) Add/standardize object fields in new().
   - Ensure _title exists and defaults to undef.
   - Ensure _scope exists and defaults to global (or undef if global=undef convention).

2) Introduce explicit global section parser.
   - Add parse_global_section (or parse_global).
   - It should parse 0..n global directives according to policy.

3) Update parse() to focus on structure.
   - parse_global_section
   - parse_mode
   - parse_language
   - parse_model
   - segment sequence
   - parse_end

4) Make segment scope explicit.
   - In parse_segment / block entry, set _scope to data|code|stack.
   - Prefer local $self->{_scope} = ... for automatic unwind on failure.

5) Enforce TITLE cardinality.
   - In parse_title, on second match fail as duplicate.
   - Persist first value to _title.
   - Emit AST title from _title at root construction.

6) Enforce LOCALS scope if “code-only” policy is accepted.
   - Allow in code scope.
   - In data/stack/global scope, if matched: fail with explicit message.

7) Unify optionality handling.
   - Use one consistent pattern for optional directives in section/block parser alternatives.
   - Remove scattered top-level probing where scope-local parsing should own the directive.

8) Reduce eval-based control flow where feasible.
   - Align parse_language style with parse_mode-style required checks and explicit fail messages.

9) Keep DISPLAY footprint minimal.
   - No persistent field needed unless reproducibility/auditing requires it.

10) Update POD.
   - Add INTERNAL STATE section.
   - Add directive legality matrix (scope/cardinality/effect).

Implementation caution: sequence_of/commit behavior
- Duplicate detection inside sequence parsers must fail hard (not silently terminate sequence).
- Commit placement determines whether failures propagate vs become normal sequence stop.
- For duplicate 0..1 directives, commit before fail after confirmed match so users get a clear syntax error.
